# Call recovery

compose/world/integrate/realize return runId and send progress every five seconds (notifications/progress when the client sends a progress token, otherwise informational logs). A call never runs into the platform's 300-second limit: when its time budget runs out it saves its progress and returns status in_progress. Then repeat EXACTLY the same call (same arguments and requestKey) right away: it resumes from the checkpoint, and finished stages and bought takes are not redone or re-bought. Repeat until the status is final; a run that makes no progress on two consecutive attempts fails and keeps its checkpoint. After a client timeout call satie_run (omit runId to list recent runs) or repeat the identical call: completed results replay without spending, a live call is not duplicated, and a call whose server died resumes after six minutes. Default requestKey is a stable argument hash; use a new key only for an intentional new paid attempt, and never change the arguments to retry. Ordinary pooled takes are reusable; unique or explicitly replaced takes can cost again. Recovery lasts seven days. Never keep blindly retrying composition with new keys. status.billingMode distinguishes metered, unmetered, unknown; a null balance alone is ambiguous.
